# Safety and responsible use

Use this framework only for systems, applications, and exercises where you
have explicit permission. A public repository is not authorization to test a
third-party system.

## Before work begins

- Write down the owner, scope, time window, and permitted techniques.
- Confirm a safe contact and an emergency stop procedure.
- Decide what data may be collected and where it may be stored.
- Start with the least-impactful checks and respect rate limits.

## During work

- Stay inside the written scope; pause when scope is ambiguous.
- Avoid accessing, retaining, or sharing unrelated personal data.
- Keep credentials and tokens in local secret storage, never in commits,
  issues, logs, examples, or screenshots.
- Prefer synthetic fixtures and local test environments for demonstrations.
- Record failed attempts and limitations honestly.

## Review and publication

Validate findings before reporting them. Redact identifiers and payloads that
are not needed to explain the issue. Review every file for private information
before sharing a branch, archive, or screenshot. Remove local artifacts only
after confirming that retention is not required by the owner or policy.

If you discover a problem in this framework, report it privately to the
maintainer rather than publishing sensitive details in an issue.
